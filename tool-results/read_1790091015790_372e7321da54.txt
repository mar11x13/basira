     1→# BASIRA — Islamic Guidance Application — Worklog
     2→
     3→Project: BASIRA (بصيرة) — a trustworthy Islamic guidance app.
     4→Stack: Next.js 16 (App Router, port 3000, single visible route `/`), TypeScript, Tailwind CSS 4 + shadcn/ui, Prisma + SQLite (db/custom.db), z-ai-web-dev-sdk (backend only).
     5→
     6→## Core principles (from product spec)
     7→- Accuracy before speed. NEVER invent Quran/hadith references. Unverifiable claims must be flagged as unverified.
     8→- Source hierarchy: QURAN → authentic hadith (Sahih al-Bukhari core) → other collections → scholarly views → general guidance. Every answer shows its source category.
     9→- Knowledge stored separately from AI logic in a structured DB (SourceText records) with verification status, reviewer, audit trail, admin panel.
    10→- Ask BASIRA = retrieval-grounded LLM answers with citation verification pass ("no hallucination mode").
    11→- Differences of opinion presented respectfully; no takfir; complex matters → consult qualified scholars.
    12→- Mobile-first, RTL/Arabic first-class, elegant emerald/gold design, no blue/indigo.
    13→- Only `/` page route visible; all views are client-side sections. APIs under /api/*.
    14→
    15→## Architecture decisions
    16→- Anonymous cookie session (basira_sid) → UserProfile row. Minimal data, deletable (privacy by design). No NextAuth to keep data minimal.
    17→- SourceText single table for all source types (QURAN, HADITH, DUA, DHIKR, FIQH, GLOSSARY, SEERAH, SCHOLARLY, GENERAL) with type-specific fields, topics/keywords, verificationStatus (VERIFIED | REFERENCE_PENDING | DISPUTED), audit fields.
    18→- Hadith numbering note: follows widely-used English edition numbering (Darussalam / sunnah.com); records where the number could not be reliably confirmed carry hadithNumber = null + referenceNote → shown as "reference pending verification" badge. Translation source: "BASIRA Simple English rendering (public domain)".
    19→- Full Quran reading = integration layer: /api/quran/surah/[id] tries external api.alquran.cloud (Uthmani + Pickthall public-domain translation), caches to DB (quran cache table), falls back to curated local ayahs with honest status labels.
    20→- Prayer times computed locally (PrayTimes-style astronomical algorithm), methods (MWL/ISNA/Egypt/UmmAlQura/Karachi), madhhab-aware Asr factor.
    21→- Hijri via Intl islamic-umalqura with moon-sighting caveat.
    22→- Daily content rotation deterministic by day-of-year.
    23→- Admin: passcode gate (ADMIN_KEY env, default basira-admin-999), full CRUD + audit log + review workflow + AI answer review.
    24→- Learning paths: static path definitions referencing SourceText records; progress rows; no leaderboard.
    25→- Notifications: optional browser Notification API reminders while app is open (limitation documented).

   232→## Key architecture facts for future agents
   233→- All religious content lives in SourceText table (slug-addressed) — the ONLY citable material. NEVER add content without a real, checkable reference; hadith numbers you cannot confirm → hadithNumber NULL + referenceNote (UI shows "reference pending" badge — this is a feature).
   234→- /api/ask pipeline: safetyCheck → retrieveForAI (14 records) → grounded system prompt (src/lib/ai.ts) → z-ai-web-dev-sdk (backend only) → verifyAnswer (strips/flags unmatched [S#] tokens, rephrases unattributed "Allah says/Prophet said", never fabricates on LLM failure — falls back to retrieval-only display). Keep this contract intact.
   235→- Seeds: prisma/seed-data/*.ts → bun prisma/seed.ts (wipes + reseeds SourceText; bookmarks cascade).
   236→- Store: src/lib/store.ts (zustand) drives client-side navigation (view/viewParams).
   237→- Shared UI: SourceCard / RecordDialog / ArabicText / ViewHeader — render records through these, never hand-roll citations.
   238→- Admin key: env ADMIN_KEY, default "basira-admin-999".
   239→- Fonts: declared in globals.css :root (NOT inline body styles — Tailwind v4 @theme inline resolves at :root).
